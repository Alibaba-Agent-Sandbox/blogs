A coding agent's day goes like this: read the task, write a script, and immediately want to run it.

The script was just generated by a model and you have not read every line. It might read a directory it should not, install a dependency you have never heard of, or simply loop forever. Run it on your own machine and you are the one cleaning up.

This post uses one small case to show how to hand the "run" step to a disposable sandbox: destroy it when done and nothing is left behind.

## The scenario

You ask the agent to analyze a sales file: total the amount per region, highest first. The agent writes a Python script. What we do:

1. Create a sandbox.
2. Put the data file in it.
3. Run the agent's script inside the sandbox.
4. Get the result back.
5. Destroy the sandbox.

Nothing the agent wrote needs to be installed on your machine, and the script never touches your files.

## Setup

The default provider is Alibaba Cloud Agent Sandbox Express Edition (`alicloud-express`), which needs an API key.

Install `abx` with one command. On macOS or Linux:

```bash
curl -fsSL https://raw.githubusercontent.com/Alibaba-Agent-Sandbox/agent-sandbox/main/install.sh | sh
abx --version
```

On Windows, in PowerShell:

```powershell
irm https://raw.githubusercontent.com/Alibaba-Agent-Sandbox/agent-sandbox/main/install.ps1 | iex
abx --version
```

The npm package is coming and is not yet published (`npm install -g @agent-sandbox/cli`). You can also build from source, which needs Node.js 20 or newer:

```bash
git clone https://github.com/Alibaba-Agent-Sandbox/agent-sandbox.git
cd agent-sandbox
npm ci
npm run build
npm pack
npm install -g ./agent-sandbox-cli-0.3.0.tgz
abx --version
export ABX_SANDBOX_API_KEY="<YOUR_API_KEY>"
```

Two Python packages share one version. Install `agent-sandbox-client` on your machine (the client; `import agent_sandbox` is unchanged). Install `agent-sandbox-server` inside a template image (the HTTP service the platform starts). The client depends on `agent-sandbox-server` of the same version, so a client install also provides `agent_sandbox.server` locally. Do not run `pip install agent-sandbox`: that name on PyPI is an unrelated project. Extras on the client are `fast`, `session`, `mcp` and `declarative`; `agent-sandbox-client[all]` installs those.

```bash
pip install agent-sandbox-client
pip install "agent-sandbox-client[all]"
pip install agent-sandbox-server
```

## With the Python SDK

Here is the whole script. `AGENT_CODE` is the part the agent generated; we hand it to the sandbox as is.

```python
import asyncio
from agent_sandbox import Sandbox

CSV = """region,amount
hangzhou,120
beijing,80
hangzhou,45
shanghai,200
beijing,30
"""

AGENT_CODE = '''
import csv

totals = {}
with open("/home/user/sales.csv", newline="") as f:
    for row in csv.DictReader(f):
        totals[row["region"]] = totals.get(row["region"], 0) + int(row["amount"])

for region, amount in sorted(totals.items(), key=lambda kv: -kv[1]):
    print(f"{region:<8}{amount:>6}")
'''


async def main():
    async with await Sandbox.create(template="base") as sandbox:
        await sandbox.files.write("/home/user/sales.csv", CSV)
        result = await sandbox.run_code(AGENT_CODE)
        print(result.text)
        print("exit code:", result.exit_code)


asyncio.run(main())
```

A few things to notice:

- `async with` destroys the sandbox on exit, whether the script succeeded or raised.
- `run_code` runs code in the sandbox's interpreter. For a shell command use `sandbox.commands.run(...)`.
- Check `result.exit_code` and `result.stderr`, and hand the error back to the agent so it can fix its own script. That is a complete write, run, fix loop.

The script prints:

```text
shanghai   200
hangzhou   165
beijing    110
```

## With the CLI

The same flow by hand with `abx`:

```bash
abx create --template base
abx upload <sandbox-id> ./sales.csv /home/user/sales.csv
abx upload <sandbox-id> ./analyze.py /home/user/analyze.py
abx exec <sandbox-id> -- python /home/user/analyze.py
abx kill <sandbox-id> --yes
```

`analyze.py` is the script inside `AGENT_CODE` above, and `<sandbox-id>` is the value `abx create` prints. The result prints in your terminal; use `abx download` when you need a file back. Always `abx kill` when you are done: a sandbox uses quota for as long as it lives, and `abx list` shows everything still running.

## Let the agent call it itself

If you would rather skip the glue code, let the agent in your IDE use the sandbox over MCP:

```bash
abx mcp install --target cursor   # or claude, vscode
```

From then on creating a sandbox, moving files, running code and destroying it are tool calls.

## What you get

- **Isolation**: the agent's code runs in a remote, disposable environment and neither reads nor changes your local files.
- **Disposability**: the sandbox is destroyed afterwards, so wrong dependencies and temp files do not linger.
- **Repeatability**: every run starts from the same template, so the same input gets the same environment.

It is not magic. Code in the sandbox can still use whatever you give it: the files you upload and the environment variables you inject. **Do not put secrets in a sandbox that does not need them.**
