# Decision: Explain native Crush as a code-delivery workflow

Status: proposed

## Problem
Crush needs its own practical article with real configuration, source repair,
artifacts, alternate consumers and model switching, beyond version inspection.

## Decision
Publish the actual Express repair/generation experience, attach executed output,
its original report bytes and the unchanged complete SDK example. Explain explicit
tool permissions, startup settings, cleanup, extensions and the native FSL license.

## API Design
N/A — article only; uses the existing three named commands and CLI/SDK/HTTP.

## Alternatives considered
Do not describe build/create alone as usage, reuse old generated files for another
consumer, assume host exports reconfigure a running instance, or call FSL MIT.

## Dependencies
https://github.com/Alibaba-Agent-Sandbox/awesome-templates/pull/255 owns the actual
receipts. Refs https://github.com/Alibaba-Agent-Sandbox/blogs/issues/16. Qualification
is reviewed independently in Registry after source acceptance lands.

## Test Strategy
Use actual unchanged-test/held-out repair evidence and three literal generation
alternatives. Independently execute downloaded code, retrieve all three reports,
verify configuration and owned cleanup, validate assets and website routes.

## Acceptance criteria
The one case, assets, records and current-head checks publish. The overall50-case
series remains incomplete; no other agent gets an inferred pass.
