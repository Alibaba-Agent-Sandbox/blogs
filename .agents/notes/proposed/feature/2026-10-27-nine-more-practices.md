# Decision: Publish nine additional practical template cases

Status: proposed

## Problem
Every used template needs its own practical case showing setup, real work, results,
public entry points, extensions and cleanup instead of a test diary.

## Decision
Publish nine separate Copilot/Muse/Codex/session/document/media/OCR/browser/compiler
cases with exact executed SDK attachments and actual generated outputs. Use specific
source-repair/session/conversion/business results and template-specific boundaries.

## API Design
N/A — article/asset changes only. Preserve actual typed arguments, startup variables,
protocols, return values and lifetime/authentication distinctions. No invented API.

## Alternatives considered
A general article or version-only walkthrough cannot convey each actual business
workflow. Do not publish protected benchmark content, private endpoints or credentials.

## Dependencies
Producer https://github.com/Alibaba-Agent-Sandbox/awesome-templates/pull/263 owns
actual exact-input receipts and complete public-method audit, including all15
Codex session/configuration/artifact routes. Refs
https://github.com/Alibaba-Agent-Sandbox/blogs/issues/16.

## Test Strategy
Review each actual original source repair or utility output, unchanged complete
SDK program, literal CLI/HTTP, second configured agent model and independent cleanup.
Validate33 posts and source-relative attachments, sync/build website, read both
language routes and actual copied assets, then run secret/diff checks.

## Acceptance criteria
Nine cases publish after producer evidence and current-head checks. Registry review
is a separate producer-bound delivery. The full50-template series remains open.
