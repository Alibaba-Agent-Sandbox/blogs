# Decision: Document actual OpenSandbox practical profiles

Status: proposed

## Problem
Individual practical cases describe Express business use but readers also need the
actual OpenSandbox platform and endpoint settings, especially native IDE cookies
and Chrome CDP application authentication across the server proxy.

## Decision
Add per-case OpenSandbox steps only after full original native and fresh literal
CLI/full README SDK/direct HTTP business execution. Preserve actual case outcomes,
attachments, account boundaries and cleanup; use a practical workflow perspective.

## API Design
No API changes. Existing provider selection and endpoint settings are explicit.
IDE uses cookie-preserving direct endpoints; Chrome keeps native VNC authentication
and application-token fallback without overriding gateway credentials.

## Alternatives considered
Inferring portability from image/creation/health or publishing unavailable native
vendor-account/interpreter workflows would overstate the actual delivered behavior.

## Test Strategy
Validate every post frontmatter/local asset, configured-secret/diff checks, explicit
website blog sync/build and actual route/attachment output. Link source-bound real
provider method/artifact/cleanup evidence, never replace it with prose checks.

current-head blog checks, website integration and final public readback must pass.
