# Decision: Publish seven individual native-agent practical cases

Status: proposed

## Problem
Each used native coding template needs its own practical account of configuration,
work, results, model switching, integration and cleanup, with its actual artifacts.

## Decision
Publish separate Goose/Pi/DeepAgents/Kimi/Grok/Cline/Prime cases. Each contains its
own native version/behavior and exact command, credentials names, complete executed
SDK program, generated code and original report bytes. Describe the real source
repair plus downloadable generation workflow from a practical delivery angle.

## API Design
N/A — article/asset changes only. Preserve actual typed arguments, workspace paths,
startup settings, return kinds and bounded upstream capability scopes.

## Alternatives considered
Do not publish one generic post, invent generated results, call version inspection
full use, import workstation login, or imply all optional hosted subscriptions and
upstream integrations passed. Keep failures in source-owner engineering evidence.

## Dependencies
https://github.com/Alibaba-Agent-Sandbox/awesome-templates/pull/260 owns individual
core/docs receipts and complete method audit. Source acceptance must land before
consumer merge. Refs https://github.com/Alibaba-Agent-Sandbox/blogs/issues/16.

## Test Strategy
Review actual source repair/unchanged original tests/held-out results, fresh three
consumers and reports, both actual configured models and independent owned cleanup.
Validate23 posts, every attached artifact and both language preview routes.

## Acceptance criteria
Seven practical posts and actual assets publish after producer acceptance and
current-head checks. Each template's Registry promotion is independently reviewed;
full50-template series remains open.
